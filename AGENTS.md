**Doc conventions. Compression passes on 2026-08-02 and 2026-08-26 restored these; please hold the line.** Four rules, each of which a pass has had to re-apply:

1. **A section that is fully done moves to the archive the SAME SESSION**, leaving at most a one-line pointer. A section reading `✅ ALL DONE, archived` is not a pointer.
2. **STATUS.md holds *state*, not a session-by-session changelog.** That is what git log and the archive are for. It reached 37 KB of dated narrative once.
3. **An invariant in this file is the RULE, in one to three lines, plus a `→` pointer to its memory file.** The incident behind it (measured numbers, why nothing caught it, what was tried and failed) belongs in that memory file. This file is loaded on EVERY session, so the narrative is not free; it reached 56 KB of write-ups duplicating memory once.
4. **An index entry is a hook**: enough to answer "do I need to open this?", and nothing more. That applies to the doc map above and to the memory index.

**Budget, measured at the top of any hygiene pass:** always-loaded (`CLAUDE.md` + this file + the memory index) under ~25 KB; orientation (plus STATUS.md + TASKS.md) under ~50 KB. CI warns when `TASKS.md` passes 200 lines; it has blown past it twice.

⚠️ **The ~25 KB figure above is WRONG and has been measured to be unreachable (2026-09-02). Do not chase it.** Two compression passes took this file 56.1 → 52.7 KB with all **93 invariants and 40 `⚠️` sub-rules** intact, and that is where careful rewriting tops out: the remaining bullets average **441 bytes**, which is the rule plus its sub-rules plus a pointer and almost no narrative left to cut. Getting to 25 KB would leave ~55 bytes per rule — one sentence, no pointer, no sub-rules — so it means **deleting invariants, not compressing prose**.

**The byte budget was measuring the wrong thing.** This file's size is a function of how many rules it holds, not how verbosely it holds them, and the rule count grew from ~40 to 93 while the number stayed put. The question worth asking of this file is not "is it under 25 KB" but **"has every rule in it earned its place, and is each one the RULE rather than the story?"** — and the story belongs in the linked memory file.

**So: ~55 KB is the honest ceiling for the always-loaded set.** Nils delegated this on 2026-09-02 ("compress agents.md the way you think is right"), and the call was to keep every invariant inline rather than move a category behind a pointer. These rules exist *because* somebody did not know they were touching that subsystem; a pointer only helps a reader who already worked that out, which is the one reader who did not need it.

**2026-10-23: the one case where a rule DOES leave this file is when the code it protects is deleted.** The old site's 64 rules went to `docs/archive/old-site-invariants.md` with its code, and this file went 80 → ~45 KB. A rule about code that still runs stays here.

## Load-bearing invariants (don't relearn these the hard way)

**Each line is the RULE. The incident that produced it (measured numbers, why nothing caught it, how it was found) is in the linked memory file, which you read BEFORE touching that subsystem.** Compressed 2026-08-26; nothing was dropped, only moved.

### Data, sync, and the database

- **The prune invariant: a sync pull that fails must THROW, never return `[]`/partial.** The app's Trakt sync (`mobile/src/lib/traktSync.ts`) and its state pull (`stateSync.ts`) delete every row missing from a successful pull, so a swallowed error wipes the user's library. ⚠️ So does a pull that outlived its session, or a run that ignores an edit made while it read Trakt: both are guarded since 2026-10-23 (the session counter in `AuthProvider.tsx`, `withoutRowsChangedDuringRun`). A pull that legitimately found nothing may return `[]`. **Anything a pull carries beyond ids inherits this**, so `undefined` ("this pull says nothing about X") and `[]` ("authoritative, and there is none") must stay distinct. Gate on a declared capability (`capabilities.episodes.read`), never on a sniff of the returned shape. → [[trakt-sync-completeness]]
- **A per-user DISPLAY preference must never reach a sync pull.** `users.platforms` and `users.media_types` (migrations 24/25) filter what a person SEES. `pruneWatchlist`/`pruneLibrary` read "absent from the pull" as "removed upstream", so filtering a type or platform at the pull layer would DELETE every matching row. Turning Games off has to leave the rows exactly where they are. The same rule bars these from `home_snapshot`/`calendar_snapshot` (viewer-independent by contract) and from the Fandex Score (every facet weight is a deviation from the user's GLOBAL baseline, so dropping a type moves the score of everything else). → [[user-display-preferences]]
- **An OAuth callback that finds an EXISTING identity must check who owns it.** Three outcomes, not one: no session → log in as the owner; owner is this session → refresh the tokens; owner is someone else → merge or refuse, never silently no-op. ⚠️ A merge switches which user the session is for, so it must set a NEW session cookie and move rows via the schema-derived `userScopedTables()`, the same list erasure uses. ⚠️ Refuse rather than invent a conflict rule when both accounts hold per-item state: `user_item_state` is unique on `(user_id, media_item_id, source, relation)`, so a blind move collides and `OR IGNORE` silently drops somebody's ratings. → `src/lib/accountMerge.ts`, [[account-merge-and-identity-ownership]]
- **The thin-write / pool rule:** a discover-time write is insert-only and stamps `browsed=1` / projection version `0`. It must never overwrite or degrade a real synced/ingested row. → [[data-model-gaps-and-plan]]
- **Erasure is schema-derived, and a `user_id` column is what makes a table personal.** `deleteAccount()` finds targets by reading `sqlite_master` for that literal column name. Name it anything else and GDPR erasure silently skips it. A CATALOG table must NOT have one. `/api/account/export` uses explicit column lists, so a new user-scoped table needs a block added there BY HAND. → [[account-erasure-and-export]]
- **A provider id is unique only WITHIN a media type, so `media_links` is keyed `(source, source_id, media_type)`** (migration 23). Trakt and TMDB number movies and shows in SEPARATE sequences: trakt 386 is both *Being John Malkovich* and *SpongeBob SquarePants*. Every lookup that turns a provider id into an item must carry the type; without it the second work to sync overwrites the first's row, merging one work's links, genres and watch history into the other. `findMatchingItem` was always type-filtered, which is why this hid. → [[cross-type-identity-merge]]
- **Before a `PROJECTION_VERSION` bump**, check whether lazy self-heal already covers it. → [[lazy-heal-vs-mass-reprojection]]
- **An index whose aggregate reads a column must COVER it.** `MAX(ml.last_synced)` through `idx_links_item` fetched every matching `media_links` row, and those carry ~7 KB of `raw_data` each: tens of MB of pages to collect one integer per row. **41.5 → 1.0 ms** with `(media_item_id, last_synced)`.

### Providers, caching, and cost

- **Per-source FAILURE isolation is not per-source LATENCY isolation, and the breaker must THROW.** `http.ts` has a per-host circuit breaker plus an optional `budgetMs`; browse paths pass `BROWSE_BUDGET_MS`, sync/pull deliberately keeps its unbounded budget. `ProviderUnavailableError` must never be a fabricated Response: a synthetic 503 reads as `!res.ok` to the pull adapters and turns an outage into a wiped library under the prune invariant. Browse opts into degradation explicitly (`bestEffort`); pull code keeps throwing. → [[provider-latency-isolation]]
- **A provider's response SHAPE is not verifiable from its documentation, and a mocked test of an assumed shape proves nothing.** When an integration returns nothing, probe the payload before theorising about the code, and prefer a check the environment can actually run (a call count) over asserting a payload you had to invent. → [[trakt-episode-endpoints]]
- **A provider call carrying only an APP credential must opt into the 401/403 latch with `appScopedAuth: true`.** Five consecutive 401/403s open the host for 15 min, doubling to a 6 h ceiling; any other response clears the run. ⚠️ Opt-in is per CALL SITE, not per host: RAWG and TMDB serve app-key and per-user calls from the SAME host, so counting a user-scoped 401 would let one expired token stop the provider for everybody. `src/lib/httpCallSites.test.ts` fails if an `httpFetch` carries an app key without the flag. → [[provider-quotas-and-scale]]
- **A cache goes through `sharedCache(name, opts)`, NEVER `new BoundedCache()`.** Next resolves a module into a different bundle per route kind, so module-level state is per-bundle, not process-global, which silently broke the circuit breaker for three weeks. `sharedCache` pins by name to `globalThis`; the name IS the identity, so two caches sharing a name share STORAGE. Bounds are ENTRY COUNTS, not bytes (`GET /api/dev/dbsize?caches=1` prices an entry). `vitest.setup.ts` clears them in a global `beforeEach`. It has to, since a pinned cache survives between tests. → [[provider-quotas-and-scale]], `docs/scalability.md` §6
- **Identical WARM and COLD timings on a route mean there is no cache at all**, and that is a cheaper diagnosis than reading the code. Every provider boundary is cached now; if you add one, cache it, pin it to `globalThis`, and **never cache an empty result**, which pins an outage in place for the whole TTL. → [[browse-page-cache-and-crawl-dead-ends]]
- **`openProviderCircuits: {}` is not a health check.** → [[facet-cache-and-provider-latency-masking]]
- **IGDB runs behind a KILL SWITCH: `IGDB_ENABLED=0` stops every call, default ON.** Its licence question is open, so the decision was to continue and make a "no" cheap. `igdbKillSwitch.test.ts` fails any export in `sources/igdb.ts` reaching `igdbQuery` without the guard. `scripts/purge-igdb.mjs` removes what is stored: links, never items. ⚠️ **Games are now IGDB-ONLY** (RAWG retired 2026-09-02), so flipping this switch takes games' browse to nothing rather than halving it. ⚠️ Default-ON is correct: a typo must leave the site working. → `docs/catalog-growth.md`
- **A SAFETY GATE read at module load is a gate nothing tests.** Three shipped that way in one session (the backfill ceiling, the housekeeping threshold, the browse minimum) and all three had a test silently asserting the DEFAULT instead of the behaviour, because setting the env var in a test does nothing after the module is loaded. Read a threshold or a switch at CALL time — `backfillMaxItems()`, `housekeepingStartMb()`, `catalogBrowseMin()`, `igdbConfigured()` are the shape.
- **A provider's RETENTION cap is a separate question from its commercial tier.** TMDB caps caching at **six months** (API Terms §1.C): an AGE cap, not a size one, so a stored catalog is fine and an unrefreshed one is not. `healLinks` re-fetches on PROJECTION VERSION and never on age, so `lib/retention.ts` marks ageing links un-projected instead. ⚠️ **IGDB is unresolved and enforces nothing on purpose**: the Twitch DSA allows a 24-hour cache or prior written authorization, which its own webhooks product contradicts. Do not pick a number. → `docs/catalog-growth.md`
- **Check a provider's USAGE TERMS before its capabilities**, and treat a `PLATFORMS.md` capability cell as a claim about code. Two of them were wrong. → [[platform-integration-architecture]]

### The Cloudflare Worker and D1 (`worker/`)

The data rules above carry over. These are the ones that are NEW there. → `docs/worker.md`, [[cloudflare-worker-d1]]

- **A D1 row write is the budget, and every index is one more.** D1 Free stops every query, reads included, for the rest of the UTC day past 100,000 rows written. A natural key is the PRIMARY KEY of a `WITHOUT ROWID` table; an index exists only where a request path needs it. Price a new table or index in writes per row before adding it. Anything a stranger can trigger that writes goes behind `spend()` in `budget.ts`.
- **A D1 row READ is a budget too: MEASURE a new query's `rows_read`, never estimate it.** Free stops every query past 5 million rows read in a UTC day, `/v1/health` included. One join left to the planner read every TMDB link per call and spent the day in 35 calls (2026-10-10). Pin the join order (`CROSS JOIN`, `INDEXED BY`) and assert the plan and `meta.rows_read` in a test. → [[cloudflare-worker-d1]]
- **Two counts are KEPT, and the statement that changes what one counts must drop it in the same batch** (`worker/src/keptCounts.ts`). A user's state counts live on the `users` row, the pool's size in `kv`; an unchanged ask is one row where it was 14,899 and 4,561. A new write to `user_item_state`, `user_episode_state`, `user_hidden_items`, or to a title's `browsed`, owes a drop, and `keptCounts.test.ts` fails until it is listed. ⚠️ The pool's size must never be answered too LOW: a device holding more titles re-downloads its catalog on every sync. ⚠️ No triggers: D1 adds a trigger's row changes to the firing statement's `meta.changes`. ⚠️ After SQL by hand or a rollback, NULL the three `counted_*` columns and delete `pool_count`. → `docs/worker.md`, [[cloudflare-worker-d1]]
- **D1 has no interactive transaction, so the schema is the lock.** `db.batch()` is atomic; a read then a write is not. Creating an item is ONE batch whose link insert is a plain `INSERT` (never an upsert), so a lost race fails the whole batch and leaves no orphan. Do not "simplify" that insert into `ON CONFLICT`.
- **A route anybody can call that reads many rows needs a limiter AND a daily cap**, like a write. `/v1/lookup` (2,000 refs, no sign-in) and `/v1/catalog/delta` had neither until 2026-10-23: about a thousand scripted calls would have spent the day's reads. They sit behind `RL_READ` and `spend()` now. A new open route that reads more than a handful of rows gets the same. ⚠️ Per-user too: one account may spend at most `DAILY_USER_WRITE_CAP_PER_USER` of the shared write cap (`me.ts`).
- **`caches.default` does nothing on workers.dev.** The API is `api.fandex.org` since 2026-10-23 and the app's default points there; the workers.dev address still answers for APKs from before. An edge-cache hit is handed on with the short `Cache-Control` (`cachedAnswer`), never the edge's own week-long one. → [[cloudflare-worker-d1]]
- **A file served from fandex.org that a stranger can make the Worker fetch is checked by its BYTES.** The cover route (`covers.ts`) keeps JPEG, PNG and WebP by magic number and sends a sandbox CSP: an SVG is an `image/*` type that runs script on the site's origin, where the web session lives.
- **Nothing is parsed on a read.** A request has 10 ms of CPU. Docs are serialised at write time and spliced into responses as strings; lists are aggregated to JSON inside SQLite. A `JSON.parse` on a list path is the regression.
- **Board games call BoardGameGeek only with `BGG_TOKEN`, and a page showing their data must credit BGG.** Their terms (2025-07-02) require a registered app, a Bearer token, server-side cached calls and a "Powered by BGG" logo. Without the token the Worker answers 503 `not-configured` and `/v1/features` hides the type; never "work around" that with an unauthenticated call. ⚠️ A shelf answer (`worker/src/shelves.ts`) is edge-cached a day: bump `CACHE_VERSION` when what it answers changes. → `PLATFORMS.md`, `docs/app.md`
- **Hardcover is FACTS ONLY, and a cover is copied, never linked.** Its API Rules let a professional project use facts about books, editions and series and nothing other users made: no Hardcover rating, review, list or count of readers is asked for, stored or shown. `hardcoverPure.ts` is the guarantee (a record holds the fields it names; a test proves `rating`, `users_count` and `lists_count` never survive parsing), so do not add such a field there, to `BOOK_FIELDS`, or to `RATING_SOURCES`. A cover goes through `/v1/cover/hardcover/` and R2 `fandex-covers` (`worker/src/covers.ts`); a card or record must never carry an `assets.hardcover.app` address. ⚠️ Their free plan is **5,000 requests a day**, counted per top-level query field: every call goes through `hardcoverHalf` (`worker/src/hardcover.ts`), which spends the `hardcover` budget first and answers nothing, never a 502, when it is gone. ⚠️ `HARDCOVER_TOKEN` unset or `HARDCOVER_ENABLED=0` must leave every book route exactly as it was before Hardcover existed; the Worker suite runs with the token set and tests the off state with its own env. ⚠️ Open Library's work stays a book's identity: a Hardcover id is asked at Open Library by ISBN before anything is created (`catalog/resolve.ts`), and ISBNs are NOT cross ids. → `PLATFORMS.md`, `docs/decisions.md`, [[books-and-boardgames]]
- **A module the Worker imports must stay free of `@/lib/db` and of Node-only APIs**, transitively. `matcherPure.ts` exists for this. `npx wrangler deploy --dry-run` fails the bundle if one slips in; CI's `worker` job fails the typecheck.
- **`PUT /v1/me/state` never infers a delete.** The prune invariant moved to the client: explicit upserts, explicit deletes, no "replace this source". A server-side replace would turn a client's failed pull into a wiped library.
- **No provider token is stored in D1, and `kv` is never exported.** `user_identities` has no token column by design. `kv` holds the Twitch app token; the nightly export skips it by name and a test fails if it reaches R2.
- **A Google ID token is accepted only with the secret behind its nonce, and the argument is never optional.** The token comes back in the browser's address and lasts an hour; the secret is what ties it to the tab that asked. ⚠️ `publish.mjs` reads the route's 400 for a missing nonce as "this API checks it" before it ships a Google button. ⚠️ Scope stays `openid profile`: adding `email` is a new category of personal data and a privacy-policy change. → `docs/worker.md`, `docs/app.md` ("Google sign-in, in a browser")
- **`DEV_LOGIN` lives in `worker/.dev.vars` and nowhere else.** It is one of the two gates on `POST /v1/dev/login`, which signs anybody in as a test account; the other is a loopback host. Never a `vars` entry in `wrangler.jsonc`, never a pushed secret. ⚠️ The test pool reads `.dev.vars`, so a test of what a DEPLOYED Worker does passes its own environment. → `docs/worker.md` ("The test accounts")
- **A Cloudflare credential must never pass through a session.** Wrangler is logged in by OAuth. Secrets go from `.env` to the Worker through `worker/scripts/push-secrets.mjs`, which prints names and lengths only. An R2 or API token shown in the dashboard is Nils's to copy.

### The website (`mobile/web/`)

fandex.org is files a build writes, served without running code. → `docs/website.md`, [[website-static-build]]

- **Publish with `node mobile/web/publish.mjs`, never `wrangler deploy` by hand.** A deploy replaces every file on the site with what is in `dist/site`, a half-built folder included. ⚠️ `build | tail && deploy` deploys after a failed build: a pipe's exit code is its last command's.
- **No `not_found_handling` in the website's `wrangler.jsonc`.** With it set, Cloudflare answers a browser's navigation to an unknown address itself and never runs `worker.ts`, so every app-only address is a 404 in a browser and a 200 in curl. Test a route with `Sec-Fetch-Mode: navigate`.
- **A static item page starts the app only for a signed-in browser, and `/v1/` is disallowed in `robots.txt`.** Both keep a crawler from spending the API Worker's daily requests on a catalog sync. Do not make the bundle load unconditionally there.
- **The `/catalog/` files are the PRODUCTION catalog, and only an app with no API address configured may start from them** (`CATALOG_FILES_URL`). One pointed at another Worker would hold another database's ids and cursor. ⚠️ Decide "production" by whether an address was configured, never by comparing with the API's address: that puts the address in the web bundle and the build refuses it. → `docs/website.md` ("The catalog as files")
- **The item page's two columns are their own box (`columns`), and the full-width band comes after it, never inside it.** A sticky element stays stuck for as long as its parent lasts, and Chrome does not stop a sticky grid item at the end of its row: with the band as a third child of one grid the artwork sat under the trailer and the cast. The sticky box is the artwork's column (`art`), which holds the picture and its thumbnails. → `mobile/src/components/itemLayout.ts`
- **Anything `ItemPage` or `LegalLinks` imports must render on a server** (no database, session, router or `window` at render time), and the page must keep its heading: the build throws on a page without one.
- **`mobile/patches/expo-sqlite+*.patch` is what lets a second browser tab start, and it has to survive an upgrade.** expo-sqlite's web build locks its whole storage folder for the first tab; unpatched, a second tab of fandex.org throws at start and shows nothing. The patch falls back to an in-memory database there. `patch-package` applies it on `npm ci` (the `postinstall` script). ⚠️ Two things that look like fixes were built, deployed and failed the same day: a database file per tab (the lock is on the folder, not the file), and a Web Lock hand-over between tabs (it deadlocked behind a background tab, 0 held and 2 pending). After bumping expo-sqlite, re-make the patch and open the site in two tabs. → `docs/app.md`
- **In `mobile/`, a write transaction goes through `inTransaction` (`lib/db.ts`), never `db.withTransactionAsync`.** Two overlapping ones on expo-sqlite's single connection cancel each other, and the screen says "Could not refresh your library" over 0 titles. ⚠️ Its sibling: a screen showing your rows must say when they are still arriving (`auth.rowsSyncing`), or a fresh tab reads as an empty account and a tick made from it is a duplicate on Trakt. → `docs/app.md`
- **In `mobile/`, `router.replace` does not take a screen out of Back history.** Every screen is a tab of one navigator with `backBehavior="history"`, where a replace only jumps, so Android's Back returns to the old screen. One that must vanish removes itself on `blur`, as `open/[source]/[type]/[id].tsx` does (SM76). → `docs/archive/history.md` (grep "15th smoke test")
- **A search compares `searchKey`, never `normalizeName`, on both sides.** `normalizeName` is the matcher's stored identity key and drops every letter outside a to z ("Pokémon" is "pok mon"); changing it means recomputing every `norm_title`. `searchKey` folds accents and keeps other scripts (SM78).
- **A device learns of another device's changes only by asking: at start, on Sync, and on coming back to the app (at most once a minute).** A new way to sync must still end in `pullRows`, and a 401 on any pull signs the device out (SM77). → `mobile/src/lib/AuthProvider.tsx`
- **In `mobile/`, `catalog.release_date` is the date in the device's country; the worldwide one is `world_date`** (`lib/localDates.ts`, 2026-10-17). Every screen reads the first, so nothing else needs to know. A statement that writes the catalog writes both, through `regional_date` as `storePage` does, or a re-sync puts the worldwide day back. → [[expo-app-phase2]]
- **The series rail reads a title's RAW `ip` facets (`FacetIndex.byRawIp`), never the resolved ones.** The provider's set is the clean one (TMDB's collection, Open Library's series); bundles and hand-made attaches are what makes a franchise 40 titles. A hand attach belongs in "More from", never in a series rail. → `docs/app.md`
- **The weekly taxonomy sweep (`scripts/taxonomy-sweep/`) NEVER changes a row that was already there**: inserts only (`ON CONFLICT DO NOTHING`), a bundle or spelling that would re-point an existing alias is skipped, hand-placed tags refused, and `category-merge` runs only with `--allow-category-merge`, which the schedule never passes. Every row it writes carries one `updated_at` stamp (plus `source = 'sweep'` where the table has the column) and the undo deletes only rows still holding it. `prepare.mjs` stops when it cannot read the dismissals, and `apply.mjs` refuses without them. A new facet page kind goes in `mobile/web/worker.ts`'s `appRoute` too, or its address 404s in a browser. → [[taxonomy-sweep-weekly]]
- **In `mobile/`, a screen that re-reads on `catalog.revision` or `rowsRevision` keeps what is on screen until the new answer lands; it blanks only when it becomes another page.** A rating bumps both (it can bring a title into the pool), and a list set to null redraws its grid at the top: rating a card threw the reader back up the page (2026-10-18, `FacetScreen`, the item page's rails). → `docs/app.md`
- **In `mobile/`, a header that hides on scroll must FLOAT over its list and slide, never change the list's layout.** Moving a list under a held thumb is read as a drag, so each hide scrolled it back and showed the bar again: a flicker for as long as the thumb stayed down (2026-10-18). A list under `SubBar` takes `useBarList()` (`lib/barScroll.tsx`) for its scroll handler and its top inset together.
- **In `mobile/`, a title missing from the catalog copy is UNKNOWN, never an answer.** Any pool shrink (a fold, a purge) makes every device start its copy over and refill it page by page, so a half-empty copy is normal. Up next stored "caught up" for every show not refilled yet and kept it for up to a week. → [[expo-app-phase2]]
- **Pageviews are counted again (2026-10-10), by the website only, and the privacy policy describes exactly what `worker/src/telemetry.ts` keeps.** Counters per kind of page, no identifier. Change what is counted and the policy text in `src/lib/legal` changes in the same publish, in both languages. ⚠️ The Android app must never send the beacon. → `docs/worker.md`, [[telemetry-self-hosted]]
- **Stop the `app-web` dev server before `publish.mjs`.** Metro watches the build's output folder and Windows will not rename a watched folder, so the build's last step fails with `EPERM` however long it retries.
- **The files live on their own Worker, `fandex-web`, not on the API's.** An API deploy from a checkout with no build would otherwise empty the site.

### Routes, URLs, and SEO

- **A public item url is `/{type}/{slug}`, off a STORED, IMMUTABLE, per-type-unique slug.** Assigned once by `ensureItemSlug` (matcher.ts's create path, AFTER `remergeItem`) and never changed. The uuid is a ROW id and the boot prune deletes rows, so a uuid url 404s after a re-open. The legacy 3-segment route must stay (it 308s, and every shared link points at it). Collisions are real (40 of 2,530 within a type): first-come keeps the bare slug, the newcomer takes `-{year}`. Thread `slug` into any new card payload. `publicItemHref` otherwise falls back to the legacy url and costs a 308 per click. → [[item-urls-are-slugs]]
- **The legal surface is CLOSED and filled.** `/legal/{en,de}/{privacy,terms,support,imprint}` all carry real content; the Impressum holds a real home address and stays `noindex, nofollow, noarchive, nosnippet` and out of `sitemap.ts`. Do not add it to the sitemap, do not relax the robots directives, and do not "restore" an EU ODR/OS-Plattform link, because that platform shut down 2025-07-20.
- **Monetization is off by default and that is the legal gate, not a preference.** `MONETIZATION_ENABLED` (unset = off) makes every affiliate link inert; the first live one makes Fandex commercial under §5 DDG. Decoration runs ONLY at the two detail boundaries via `decorateItemLinks()`, never in `normalize.ts` (needs a `PROJECTION_VERSION` bump) and never in `mergeLinks()`. Every link stays a direct outbound `<a href>`: a Fandex-hosted redirect or click pixel breaks §25 TDDDG's cookie exemption *and* Amazon's terms. → [[monetization-h3]], `docs/decisions.md`
- **Counters, not events, and no `user_id`, on purpose.** A client beacon does NOT exclude crawlers. → [[telemetry-self-hosted]]

### UI, layout, and the browser pane

- **An auth gate must ASK, never disappear.** A gate that redirects, returns `null`, or renders inert "sign in to…" text is indistinguishable from a broken feature. Before gating, ask which part is actually per-user; half of one batch of six were gating the wrapper rather than the data. ⚠️ `withOptionalUser` hands the handler `session | null` — **pass the null through, never a placeholder id** (it is `persistDiscoverBatch`'s PR15 write gate). Size `anonLimit` to what the route SPENDS. Shared gate: `components/auth/SignInGate.tsx`. → [[anon-gates-must-ask-not-bounce]]
- **A component that renders `null` when empty must know WHY it is empty before it ships.** "No data yet", "the pull is FAILING", "still filling a cache" and "genuinely caught up" all read as "the feature doesn't work". Ship a `*Status`/`*Diagnostic` returning the counts that separate them, computed independently so a throw in the main path can't take the explanation down too.
- **One outcome per tap target, proven by hit-testing** (`document.elementFromPoint` across a grid of points inside a cell), not by reading the JSX. Two clickable layers in one cell means thumb placement decides what happens. **A hover affordance on a target only a thumb can reach is a defect on mobile, not a desktop bonus**. Decide which surface the control belongs to. → [[calendar-day-first-and-viewport-fit]]
- **The Google "G" is the ONE exception to the no-brand-colour rule, and it is required, not chosen.** Google's guidelines list monochrome versions under **Don't** and make compliance a condition of app verification. Drawn by `components/auth/GoogleMark.tsx` with four literal fills, never by `BrandGlyph` or `brandMarks.ts`; `brandMarksNoGoogle.test.ts` fails if a `Google` key reappears, because a monochrome G looks fine and is a silent breach. ⚠️ Read the guidelines in **ENGLISH**: the German translation inverts the background-colour rule. → [[identity-only-auth-providers]]
- **Platform colour-coding is removed site-wide. Identify a provider by its LOGO via `<BrandGlyph source="…">`, not its hex.** No brand hue in ANY state, hover included. `TYPE_COLORS` (game/movie/show) is a different axis and stays. ⚠️ The sweep missed one inline hex for five days, so **grep for a hex** before repeating "site-wide". simple-icons ships WORDMARKS that are illegible below ~20px. → [[platform-brand-marks-not-colours]]

### Tooling and lint

- **A type-only import must be written `import type`**, an eslint ERROR here, and not style. Node's native type-stripping (what `scripts/alias-hooks.mjs` gives every standalone `.mjs`) erases only *syntactically* type-only constructs, so a plain `import { Foo }` of an interface throws `SyntaxError` the moment a script reaches that module, while tsc, vitest, `next dev` and `next build` all elide it silently. Every export of `src/types/index.ts` is type-only. → [[db-migrations-and-testing]]
- **Check for a trailing newline before appending to a config file, and never let a secret reach the terminal.** `printf '…' >> .env` on a file with no final newline lands on the END of the last line: it concatenated onto `DISCORD_CLIENT_SECRET`'s value, and repairing it meant reading the line back, so the secret hit the transcript and had to be rotated. The `node -e` rule below covers TRACKED files; `.env` is untracked, which is exactly why it was not covered. ⚠️ **A secret that reaches a transcript is burned** — say so plainly and put the rotation at the top of Nils's list rather than quietly repairing the file. → [[identity-only-auth-providers]]
- **Never edit a repo file with `node -e` string slicing. Use the Edit tool.** This checkout is **CRLF**, so `indexOf('\n\n')` never matches, returns -1, and `s.slice(-1)` keeps ONE CHARACTER instead of the rest of the file. It deleted 236 of `TASKS.md`'s 254 lines and was committed unnoticed; nothing threw and the script printed "ok". ⚠️ Its sibling: **backticks inside a `node -e` string are command substitution in bash**, so a `` `path.tsx` `` in doc prose is executed and replaced with nothing. If you must script an edit, verify the line count before AND after.
- **One lint run covers all three packages** (`npm run lint` at the root, `eslint.config.mjs`), since 2026-10-23: before, only the old site was linted and the code that ships had none. Errors are only the rules that catch a real failure (`import type`, hooks called conditionally, a `//` comment rendered as JSX text); `exhaustive-deps` is a warning. Keep it at 0 errors.
- **Read eslint's `✖` TOTALS line, never `tail` its output.** The LAST line is the FIXABLE summary — "0 errors and 8 warnings potentially fixable" means none of the errors are auto-fixable, NOT that there are none. The totals line sits above it: "481 problems (1 error, 480 warnings)". A `| tail -2` reads as green and let a CI-breaking error through. `npm run lint 2>&1 | grep -E '^✖'`.
- **Do not run `eslint --fix` broadly without diffing for non-import changes**. It rewrote three `{/* eslint-disable-next-line */}` JSX comments to a bare `{ }`, destroying the directives while looking inert. → [[eslint-fix-mangles-jsx-comments]]
- **A `//` comment in JSX CHILDREN position is a TEXT NODE and renders on the page.** A *refactoring* hazard: wrapping an existing `return ( … )` in a fragment moves any `//` comment from JS position into children position. Valid JSX, so tsc, lint, tests and the build all pass. Only a human looking at the page catches it. `react/jsx-no-comment-textnodes` is now an ERROR. Re-check every comment inside a `return` you just wrapped. → [[jsx-comment-in-children-renders]]
- **`npm run lint` scans the whole cwd with no path filter**, so a stray `git worktree` under `.claude/worktrees/` gets scanned, gitignored or not (`eslint.config.mjs`'s `globalIgnores` excludes it now). If lint reports a wall of errors you don't recognize, check `git worktree list` before assuming you broke something, and **never delete a worktree you didn't create**. It may be another session's live work. Browser-verifying from a worktree needs a real `npm ci`; a `node_modules` junction fails. → [[worktree-needs-real-npm-ci]]

### Measurement discipline

- **Measure before optimising.** §A was mis-sized by 100× once, and a 58 s cold Discover load was blamed on the catalog pool for days when the pool rebuild is ~430 ms. Payload beat CPU in the one full audit. → [[perf-audit-2026-07-30]]
- **Take a time series, never a spot sample**, for prod memory, cost or DB growth. Across four incidents the obvious culprit was wrong every time, and **a WAL that will not truncate is a symptom to chase, not a high-water mark to document** (`shadowWalMb` moving across a restart separates the two). → [[prod-incidents]], [[wal-highwater-vs-litestream-stall]]
## Model/agent routing for this repo

The main session's model is whatever the human picked — this doesn't change that. It guides which model/agent tier to reach for when *delegating* via the Agent/Task/Workflow tools:

- **Bulk file search / "where is X" exploration** → the `Explore` agent at the default model. Cheap, fast, keeps the main context clean.
- **Mechanical doc maintenance** (archiving a finished phase, reformatting, renaming) → fine to delegate at low effort. Low blast radius, easy to review the diff afterward.
- **Anything touching `migrations.ts`, `matcher.ts`'s write paths, sync/pull adapters, or auth/session code** → do NOT delegate to a background/low-effort agent. These carry the invariants above (a mistake risks data loss or an auth hole) — do this work in the main loop at full effort, and verify against real `data/rr.db` behavior rather than trusting green tests alone (see [[db-migrations-and-testing]]: every DB test starts fresh, so none of them exercise the upgrade path production actually takes).
