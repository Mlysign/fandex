**Doc conventions. Compression passes on 2026-08-02 and 2026-08-26 restored these; please hold the line.** Four rules, each of which a pass has had to re-apply:

1. **A section that is fully done moves to the archive the SAME SESSION**, leaving at most a one-line pointer. A section reading `✅ ALL DONE, archived` is not a pointer.
2. **STATUS.md holds *state*, not a session-by-session changelog.** That is what git log and the archive are for. It reached 37 KB of dated narrative once.
3. **An invariant in this file is the RULE, in one to three lines, plus a `→` pointer to its memory file.** The incident behind it (measured numbers, why nothing caught it, what was tried and failed) belongs in that memory file. This file is loaded on EVERY session, so the narrative is not free; it reached 56 KB of write-ups duplicating memory once.
4. **An index entry is a hook**: enough to answer "do I need to open this?", and nothing more. That applies to the doc map above and to the memory index.

**Budget, measured at the top of any hygiene pass:** always-loaded (`CLAUDE.md` + this file + the memory index) under ~25 KB; orientation (plus STATUS.md + TASKS.md) under ~50 KB. CI warns when `TASKS.md` passes 200 lines; it has blown past it twice.

## Verifying anything behind a login

`/insights`, `/profile`, `/settings`, `/library` and `/wishlist` all render a sign-in gate for anonymous visitors (the last two since 2026-08-18, the first three since 2026-08-27), and the item-detail personal block swaps to its anon controls. Either way **the real content can't be checked without a session.** Use **`GET /api/dev/login`** — it mints one for the `users.id` in `DEV_LOGIN_USER_ID` and redirects to `/`; the local `.env` already points at the real account. Works in the in-app browser pane.

Don't hand-mint a JWT (the harness blocks it as credential-forging, correctly) and don't assume anon-only verification is the best available — that assumption is why several batches shipped "not yet verified logged-in". **Never call `/api/auth/logout` to test the anon side**: it bumps `session_epoch` and kills Nils's own browser session, which only a real OAuth round-trip restores.

The route's three fail-closed gates (`NODE_ENV !== "production"` · loopback host · a real identity row) are what keep it off fandex.org. Do not relax them, and treat it as auth code — main-loop only, per the routing rules below.

## Load-bearing invariants (don't relearn these the hard way)

**Each line is the RULE. The incident that produced it (measured numbers, why nothing caught it, how it was found) is in the linked memory file, which you read BEFORE touching that subsystem.** Compressed 2026-08-26; nothing was dropped, only moved.

### Data, sync, and the database

- **The prune invariant: a sync pull that fails must THROW, never return `[]`/partial.** `syncProvider` (`src/lib/sync/index.ts`) deletes every local entry missing from a successful pull, so a swallowed error wipes the user's library. A pull that legitimately found nothing may return `[]`. **Anything a pull carries beyond ids inherits this**, so `undefined` ("this pull says nothing about X") and `[]` ("authoritative, and there is none") must stay distinct. Gate on a declared capability (`capabilities.episodes.read`), never on a sniff of the returned shape. → [[trakt-sync-completeness]]
- **A per-user DISPLAY preference must never reach a sync pull.** `users.platforms` and `users.media_types` (migrations 24/25) filter what a person SEES. `pruneWatchlist`/`pruneLibrary` read "absent from the pull" as "removed upstream", so filtering a type or platform at the pull layer would DELETE every matching row. Turning Games off has to leave the rows exactly where they are. The same rule bars these from `home_snapshot`/`calendar_snapshot` (viewer-independent by contract) and from the Fandex Score (every facet weight is a deviation from the user's GLOBAL baseline, so dropping a type moves the score of everything else). → [[user-display-preferences]]
- **Check sync staleness PER PROVIDER, never with one collapsed `Math.max`.** A Trakt-only run made Steam look fresh and froze it for three weeks. `staleProviders()` in `syncClient.ts` is the only decider; `syncToCompletion()` takes a LIST. ⚠️ An empty list must be an explicit no-op: `/api/sync` falls back to the whole registry on an empty `providers`. → [[trakt-sync-completeness]]
- **Migrations have TWO apply paths**: in-process via `getDb()` (tests + prod) and standalone via `node scripts/migrate.mjs` (plain Node; resolves neither the `@/*` alias nor extensionless specifiers). Green tests only prove the first. After touching `migrations.ts`, run the standalone script against a DB copy. → [[db-migrations-and-testing]]
- **`db.ts`'s `CREATE TABLE`/`CREATE INDEX` block runs BEFORE migrations** and must stay valid against the OLD schema. A column added by a migration gets its index created in that *same* migration. Putting them together works on a fresh DB and silently breaks every upgrade path.
- **Any SQL reaching the SCHEMA must parse on the SQLite LITESTREAM embeds (~3.40), not the 3.53 `better-sqlite3` ships.** SQLite parses the whole schema before preparing any statement, so one unsupported construct stops the backup daemon dead while every test, the build and `/api/health` stay green. Express sorting as `ORDER BY` in a SUBQUERY, never inside an aggregate's argument list. Check new schema SQL with an OLD `sqlite3` CLI against a DB copy, and re-run the restore drill after any schema change. → [[prod-incidents]]
- **`user_library` / `user_watchlist` are VIEWS**, and a `CREATE INDEX` on either kills the next boot. → [[cache-tables-are-views]]
- **A new table referencing `media_items` must be added to `dbPrune.ts`'s `PRUNABLE_WHERE`.** The boot prune is default ON in prod and deletes `browsed = 1` rows nobody "acted on", where acted-on is a hard-coded table list. Extend the list; don't reason about whether one table implies another.
- **Any table written on a REQUEST path needs a row or byte ceiling, not just a TTL**, run on an unref'd interval in bounded batches, evicting by WRITE time (tracking reads turns every cache hit into a write). An age cap is not a size cap and a boot-only sweep is not a schedule: prod runs for days, and a crawler keeps every row inside the TTL window while the table grows all day. Deleting rows does not shrink the file, but `db.ts` VACUUMs after any migration applies, so you rarely need to act. → [[prod-incidents]]
- **The thin-write / pool rule:** a discover-time write is insert-only and stamps `browsed=1` / projection version `0`. It must never overwrite or degrade a real synced/ingested row. → [[data-model-gaps-and-plan]]
- **Erasure is schema-derived, and a `user_id` column is what makes a table personal.** `deleteAccount()` finds targets by reading `sqlite_master` for that literal column name. Name it anything else and GDPR erasure silently skips it. A CATALOG table must NOT have one. `/api/account/export` uses explicit column lists, so a new user-scoped table needs a block added there BY HAND. → [[account-erasure-and-export]]
- **A provider id is unique only WITHIN a media type, so `media_links` is keyed `(source, source_id, media_type)`** (migration 23). Trakt and TMDB number movies and shows in SEPARATE sequences: trakt 386 is both *Being John Malkovich* and *SpongeBob SquarePants*. Every lookup that turns a provider id into an item must carry the type; without it the second work to sync overwrites the first's row, merging one work's links, genres and watch history into the other. `findMatchingItem` was always type-filtered, which is why this hid. → [[cross-type-identity-merge]]
- **The pool PATCHES a content change; it must stay EXACTLY equal to a rebuild.** `unfoldEntry` is the inverse of `foldEntry` and un-counts an item's vocab with the RAW pre-alias facets it was folded with (`_cache.rawFacetsById`) — post-alias ones are a different set. A vocab that is merely close is not a small bug: `computeIdf` reads those counts, so every ranking shifts silently. Every check runs BEFORE any mutation, and a throw is answered with a rebuild. ⚠️ The changed set is `updated_at >= prevMx`, never `>`: one-second resolution means `>` silently misses a write. ⚠️ A DELETION still rebuilds (which row went is unknowable from an aggregate). → `docs/archive/history.md` (catalog growth §16)
- **A same-length payload rewrite inside one second is invisible to the facet cache**, whose token is `(last_synced, OCTET_LENGTH)`. Swapping a nine-byte genre for another nine-byte genre serves the OLD derivation, correctly. Know this before blaming code: it cost an hour once, in a test fixture. Likewise `contentSignature` cannot see a same-second re-sync at all (neither COUNT nor MAX moves) — the 5-minute pool TTL is what covers that, and any test of a re-sync must bump `updated_at` by hand.
- **Before a `PROJECTION_VERSION` bump**, check whether lazy self-heal already covers it. → [[lazy-heal-vs-mass-reprojection]]
- **A helper that signature-checks its cache must be called once per PASS, never once per item.** `getScoringConfig`, `getIpAliases` and `getItemIpOverrides` each run a `SELECT` before trusting their cache; `computeFandexScore` called all three per item, so **79% of Fandex Score CPU was cache validation** and scoring cost 105 µs/item. `scoringContext()` fetches them once: **5.1×**, byte-identical scores. Any loop over the catalog wants the same treatment. → `docs/archive/history.md` (catalog growth §4), probe with `scripts/probe-score.mjs`
- **A cache KEY must be cheaper than the thing it guards, and it must never touch a VIEW.** `librarySignature` asked `user_library` (a view of CTEs, `json_group_array` and two GROUP BYs) for a COUNT and a MAX: **69 ms per call, three calls per request**, to produce a cache key. Off the base table, with a covering index, it is **1 ms** — and `find()` went 190 → 86 ms. Sign off `user_item_state`; a per-source count is strictly more sensitive than a per-item one, and a signature only has to CHANGE. → `docs/archive/history.md` (catalog growth §11)
- **An index whose aggregate reads a column must COVER it.** `MAX(ml.last_synced)` through `idx_links_item` fetched every matching `media_links` row, and those carry ~7 KB of `raw_data` each: tens of MB of pages to collect one integer per row. **41.5 → 1.0 ms** with `(media_item_id, last_synced)`.
- **A memory fix sized from `JSON.stringify` length is sized wrong.** `poolWeight()` said the scoring pool was the biggest thing in memory; measured RETAINED heap says it is **13.5 MB of 109.6**, and `facetCache.derived` was 86 MB. The planned facet-string interning, at its theoretical best (130,737 occurrences → 22,341 objects, 5.85× reuse), saved **0.4 MB**. Serialised bytes are a growth RATE, never a target list. Measure with `node --expose-gc scripts/probe-memory.mjs`. → `docs/archive/history.md` (catalog growth §13)
- **Price a cache ENTRY before choosing its bound, and never store a field no caller reads.** `mergeLinks` returns `sources[].data` — the whole parsed provider blob — and `facetCache` stored it, which its own header forbids in as many words: **76% of a 25.5 KB entry**, and its `max: 6000` was therefore a ~200 MB ceiling. Both `/api/library` and `/api/calendar` had been dropping that field on the WIRE for a month without anyone checking the process holding the same bytes. Make the TYPE exclude it so `tsc` is the proof. → `docs/archive/history.md` (catalog growth §13)
- **A token computed in BOTH SQL and JS must be UTF-8 BYTES** (`OCTET_LENGTH` / `Buffer.byteLength`). SQLite's `LENGTH()` counts code points, JS `.length` counts UTF-16 units, so any payload with an emoji made facetCache's freshness key unmatchable: **56 of 7,006 links never once hit that cache**, invisibly, since a permanent miss only costs time. `LENGTH()` on TEXT also has to decode the string — **67–84 → 8–12 ms** over the pool. → `facetCacheFreshnessToken.test.ts`
- **A cached array indexed by POSITION may be served stale, never misaligned.** `fandexScoresFor` serves the previous scores while a chunked pass refreshes them, so no request scores the catalog; that is only safe because `poolSig` is tracked apart from `sig` ("index *i* still means `vectors[i]`" is a different question from "these numbers are current") and a moved pool is REMAPPED by id, with `NaN` → `fandexPending` for anything new. → `docs/archive/history.md` (catalog growth §12)
- **An item that is already a catalog row carries no `raw`, and BOTH uuid resolvers skip those** (`lookupExistingUuids`, `persistDiscoverItems`). `persistDiscoverBatch` passes a uuid `id` through for exactly this reason. Miss it and a whole page renders `linkable: false` — cards that look right and click nowhere. → `docs/archive/history.md` (catalog growth §10), [[anon-surface-has-no-item-links]]

### Providers, caching, and cost

- **Per-source FAILURE isolation is not per-source LATENCY isolation, and the breaker must THROW.** `http.ts` has a per-host circuit breaker plus an optional `budgetMs`; browse paths pass `BROWSE_BUDGET_MS`, sync/pull deliberately keeps its unbounded budget. `ProviderUnavailableError` must never be a fabricated Response: a synthetic 503 reads as `!res.ok` to the pull adapters and turns an outage into a wiped library under the prune invariant. Browse opts into degradation explicitly (`bestEffort`); pull code keeps throwing. → [[provider-latency-isolation]]
- **If a medium has two providers, a single-source pull is a bug.** Games are RAWG *and* IGDB in the BROWSE feed (`fetchGamePageAllSources` / `fetchTrendingGames` / `dedupeGames` in `discoverFeed.ts`, which is one correct copy; three single-source ones is how they drifted). ⚠️ **Scope narrowed 2026-08-23: the facet paths dropped RAWG entirely, and that split is deliberate.** Cutting it from browse too was tried and reverted the same day. `discoverFeedSources.test.ts` fails, because Steam has no date-windowed pagination and browse would have gone IGDB-only. When touching any games surface, check all of them: initial browse, load-more (a *different* path), trending, calendar-popular, profile. → [[provider-latency-isolation]]
- **A provider's response SHAPE is not verifiable from its documentation, and a mocked test of an assumed shape proves nothing.** When an integration returns nothing, probe the payload before theorising about the code, and prefer a check the environment can actually run (a call count) over asserting a payload you had to invent. → [[trakt-episode-endpoints]]
- **A provider call carrying only an APP credential must opt into the 401/403 latch with `appScopedAuth: true`.** Five consecutive 401/403s open the host for 15 min, doubling to a 6 h ceiling; any other response clears the run. ⚠️ Opt-in is per CALL SITE, not per host: RAWG and TMDB serve app-key and per-user calls from the SAME host, so counting a user-scoped 401 would let one expired token stop the provider for everybody. `src/lib/httpCallSites.test.ts` fails if an `httpFetch` carries an app key without the flag. → [[provider-quotas-and-scale]]
- **A cache goes through `sharedCache(name, opts)`, NEVER `new BoundedCache()`.** Next resolves a module into a different bundle per route kind, so module-level state is per-bundle, not process-global, which silently broke the circuit breaker for three weeks. `sharedCache` pins by name to `globalThis`; the name IS the identity, so two caches sharing a name share STORAGE. Bounds are ENTRY COUNTS, not bytes (`GET /api/dev/dbsize?caches=1` prices an entry). `vitest.setup.ts` clears them in a global `beforeEach`. It has to, since a pinned cache survives between tests. → [[provider-quotas-and-scale]], `docs/scalability.md` §6
- **The discovery pool must NOT be capped** (`_cache.vectors` in `discovery.ts`, ~2.6 MB per 1,000 catalog items). It is the candidate set, so truncating it silently changes every Fandex Score, "More like this" ranking and IDF weight. Measure it (`poolWeight()`) and plan for the slope. → [[data-model-gaps-and-plan]]
- **Identical WARM and COLD timings on a route mean there is no cache at all**, and that is a cheaper diagnosis than reading the code. Every provider boundary is cached now; if you add one, cache it, pin it to `globalThis`, and **never cache an empty result**, which pins an outage in place for the whole TTL. → [[browse-page-cache-and-crawl-dead-ends]]
- **Provider cost scales with CATALOG BREADTH × CRAWLER APPETITE, not pageviews, and the quota is the ceiling.** Price any new provider call on a crawlable page in cold-facet-page units via `/api/health`'s `providerCalls`. **OMDb is DELETED** (CC BY-NC at every tier; `noOmdb.test.ts` pins it out, so do not re-add) and **RAWG is off the facet paths**. ⚠️ A cold `/tag/` page should now cost 10 requests, none RAWG. That is a PREDICTION, not a measurement. → [[provider-quotas-and-scale]], `docs/scalability.md`
- **`openProviderCircuits: {}` is not a health check.** → [[facet-cache-and-provider-latency-masking]]
- **IGDB runs behind a KILL SWITCH: `IGDB_ENABLED=0` stops every call, default ON.** Its licence question is open (§17), so the decision was to keep going and make a "no" cheap. It hangs off `igdbConfigured()`, and `igdbKillSwitch.test.ts` fails any `export async function` in `sources/igdb.ts` that reaches `igdbQuery` without the guard — two already did, which turned the switch into a THROW rather than a no-op. Flipping it stops the flow; `scripts/purge-igdb.mjs` removes what is stored (links, never items: all user rows and all `media_items` survive). ⚠️ Default-ON is correct for a kill switch: a typo must leave the site working. → `docs/catalog-growth.md`
- **A WAL-mode database is the `.db` PLUS its `-wal`.** Copying only the `.db` gives a pre-WAL snapshot that reads as perfectly valid and is silently stale: it reported 1,580 projection rows against the 908 actually there, because a DELETE was still in the WAL. Copy both, or every count you take is a guess. This is also why `scripts/*` probes say to point at a COPY and mean a complete one.
- **A SAFETY GATE read at module load is a gate nothing tests.** Three shipped that way in one session (the backfill ceiling, the housekeeping threshold, the browse minimum) and all three had a test silently asserting the DEFAULT instead of the behaviour, because setting the env var in a test does nothing after the module is loaded. Read a threshold or a switch at CALL time — `backfillMaxItems()`, `housekeepingStartMb()`, `catalogBrowseMin()`, `igdbConfigured()` are the shape.
- **A background job's EMPTY answer is not the same as "finished", when the fetcher swallows failures.** The backfill retired a whole lane on one empty page because RAWG was quota-latched and `fetchGamePageAllSources` answers `[]` on failure. Count consecutive empties (three) and reset on any real page. Same `undefined` vs `[]` distinction as the prune invariant, different blast radius: a lane that silently never runs again. → `docs/archive/history.md` (catalog growth §18)
- **`strftime('%s','now')` has ONE-SECOND resolution, so it cannot order things within a pass.** Every backfill lane a pass touched shared one second, so "least recently run" could not separate them and one lane was hammered while five starved. Track what a pass has already used, and tie-break on DECLARATION order rather than alphabetically (which quietly re-prioritises the list). The same resolution is why `contentSignature` cannot see a same-second re-sync and why facetCache needs a length in its token.
- **Backticks inside `db.ts`'s schema template literal END THE STRING.** A SQL `--` comment written with ``identifiers`` is a parse error at the next quote, and the error points at the top of the block, not at your line. Cost two debugging rounds in one day. Write schema comments in plain prose.
- **A provider's RETENTION cap is a separate question from its commercial tier, and this project researched only the second.** TMDB caps caching at **six months** (API Terms §1.C) — an AGE cap, not a size one, so a stored catalog is fine and an unrefreshed one is not. `healLinks` re-fetches on PROJECTION VERSION and never on age, so nothing enforced it: `lib/retention.ts` marks ageing links un-projected, which is the queue the fill job already drains. ⚠️ **IGDB is unresolved and enforces nothing on purpose**: the Twitch DSA allows a 24-hour cache or prior written authorization, which its own webhooks product contradicts. Do not pick a number — it needs `partner@igdb.com`. → `docs/catalog-growth.md`
- **Check a provider's USAGE TERMS before its capabilities**, and treat a `PLATFORMS.md` capability cell as a claim about code. Two of them were wrong. → [[platform-integration-architecture]]

### Routes, URLs, and SEO

- **A public item url is `/{type}/{slug}`, off a STORED, IMMUTABLE, per-type-unique slug.** Assigned once by `ensureItemSlug` (matcher.ts's create path, AFTER `remergeItem`) and never changed. The uuid is a ROW id and the boot prune deletes rows, so a uuid url 404s after a re-open. The legacy 3-segment route must stay (it 308s, and every shared link points at it). Collisions are real (40 of 2,530 within a type): first-come keeps the bare slug, the newcomer takes `-{year}`. Thread `slug` into any new card payload. `publicItemHref` otherwise falls back to the legacy url and costs a 308 per click. → [[item-urls-are-slugs]]
- **Any route reading an env var to build an absolute URL must export `dynamic = "force-dynamic"`.** Next prerenders route handlers without it at build time, and Railway's build-phase env differs from runtime, so the wrong value is baked in permanently, status 200 either way. Verify in `npm run build`'s route table: `ƒ (Dynamic)`, not `○ (Static)`. → [[railway-build-vs-runtime-env]]
- **Any `NEXT_PUBLIC_*` read by a CLIENT component needs a Dockerfile `ARG`**. Server components still render it fine, so it looks like it worked. → [[next-public-env-needs-dockerfile-arg]]

### UI, layout, and the browser pane

- **An auth gate must ASK, never disappear.** A gate that `router.replace("/")`s, returns `null`, or renders inert "sign in to…" text is indistinguishable from a broken feature, and the person hitting it is least able to diagnose it. Before gating a surface, ask which part is actually per-user. Six of these shipped at once and half were gating the wrapper rather than the data. `withOptionalUser` hands the handler `session | null`; **pass the null through, never a placeholder id** (it is `persistDiscoverBatch`'s PR15 write gate). Size `anonLimit` to what the route SPENDS. ⚠️ The three pages this file used to record as bouncing (`/insights`, `/profile`, `/settings`) ASK now, through the shared `components/auth/SignInGate.tsx`. → [[anon-gates-must-ask-not-bounce]]
- **A component that renders `null` when empty must know WHY it is empty before it ships.** `return null` on an empty state discards the only evidence anyone gets, and "no data yet", "the pull is FAILING", "still filling a cache" and "genuinely caught up" all read as "the feature doesn't work". Ship a `*Status`/`*Diagnostic` returning the counts that separate the cases, computed independently so a throw in the main path can't take the explanation down with it.
- **When ONE component is fed by TWO routes, every field the shared code reads must arrive from BOTH**. The half that is missing fails silently, as an inert control rather than an error. `/library` and `/wishlist` are one component over two routes; a missing `addedAt` made the default sort do nothing for a month with 1,049 tests green, because the field is optional by design. ⚠️ **`addedAt` describes an EVENT, not the item**, so a merge cannot resolve it by keeping the richer copy, because an item in both collections has two. ⚠️ A check that names one of two surfaces sharing a component is testing the component's luck. ⚠️ **A condition on `route ===` inside such a component is a bug waiting for whichever route the nav prefers.** SM19's render cap read `route === "library"`, so the same Library tab at `/wishlist?tab=library` rendered 1,929 cards instead of 300, and `AppNav` links only the uncapped one. Branch on `activeTab`; `route` is for building URLs. Fixed 2026-08-27 and pinned by `components/myStuffRouteConditions.test.ts`, which fails on any `route ===` in that file. → [[shared-view-two-routes]]
- **A control the shared toolbar renders on a tab must be consulted by that tab.** SubBar puts search, type chips, sort and the Filters sheet above every list page, and MyStuffView returned early for Progress with no state passed at all — four visible controls that did nothing for twelve days. Wire them or don't render them; "they don't apply here" is indistinguishable from broken. ⚠️ **Every filter in this app is client-side, so a filtered list must be fetched WHOLE**: a filter over one page of a paged list finds only what you already scrolled past. → [[shared-view-two-routes]]
- **A client-side facet filter sees TAGS ONLY, because `/api/library` and `/api/calendar` ship `sources[].data` as `{}`.** `extractFacets` reads people, companies and franchises straight out of those blobs, so a person or studio pill silently matches nothing on Library and Wishlist — and a pill that matches nothing looks exactly like a genuine zero. Compute ids SERVER-side and match with `matchesFacetIds`; `lib/upNextFacts.ts` is the shape. Fixing the older two tabs is open in `TASKS.md`, and the payload wants pricing first (~1.3 MB on 8.9 MB).
- **Anything a CLIENT component renders must never reach a module that imports `db.ts`.** The failure is a 500 on the page with tsc, lint and every test green, because nothing but loading the page exercises the client/server module graph. The fix is a LEAF module with no imports, shared by both halves. ⚠️ `import type` is erased and always safe; a runtime value is not. ⚠️ Turbopack caches the bad graph, so delete `.next` before believing a stale `Module not found`. → [[home-snapshot-and-crawlable-rails]]
- **CSS visibility is not conditional rendering.** A `lg:hidden` tree plus a `hidden lg:block` tree puts BOTH in the DOM, so every client island in them mounts twice and images inside `display:none` still download. Switch the *layout* with CSS and render the CONTENT once. Static paired title/nav elements are fine and deliberate (it removes one from the a11y tree). → [[item-detail-mockup-rebuild]]
- **A section above the fold that renders `null` while loading is a layout shift, and a skeleton alone cannot fix an auth-gated one**. The client only learns someone is signed in when the same round-trip lands. Read the session in `page.tsx` for a `signedIn` boolean and pass it down; a crawler is anonymous and gets byte-identical HTML. ⚠️ A placeholder must match the real box, MEASURED. The first attempt was 36px short, plus 4px of scroller padding, and those deltas are additive. → [[home-snapshot-and-crawlable-rails]]
- **One outcome per tap target, proven by hit-testing** (`document.elementFromPoint` across a grid of points inside a cell), not by reading the JSX. Two clickable layers in one cell means thumb placement decides what happens. **A hover affordance on a target only a thumb can reach is a defect on mobile, not a desktop bonus**. Decide which surface the control belongs to. → [[calendar-day-first-and-viewport-fit]]
- **A page-level `min-h-screen` inside a padded wrapper guarantees the page scrolls**: 100vh plus the padding exceeds the viewport by construction. `<body>` already carries it. Derive bottom padding from `--size-nav-bar-mobile` plus `env(safe-area-inset-bottom)`, never a flat guess. **Measure `scrollHeight - innerHeight` and expect 0.** → [[calendar-day-first-and-viewport-fit]]
- **When a surface must not jank, the fix is a layout that cannot change size, not smoother transitions on one that does.** Four separate complaints on `/calendar` were one fault: page HEIGHT and SCROLL POSITION were being used as UI. It is now exactly one viewport tall and never scrolls. What that forced: measure a budget with a `ResizeObserver` on a `flex-1` element (its height comes from the VIEWPORT, so it can't feed itself) and give children explicit pixel heights that sum back; let the arithmetic decide the design (the month collapses to whole weeks rather than shrinking rows); give BOTH states of a disclosure the same size; put a status line in a slot that always exists. ⚠️ `overflow-hidden` on the page root makes it the sticky SCROLLPORT, which broke `md:top-14`. → [[calendar-day-first-and-viewport-fit]]
- **A `position: fixed` overlay is trapped by ANY ancestor with a `transform`, `translate`, `rotate`, `scale`, `filter` or `container-type` — including a ZERO-valued one.** Tailwind v4's `translate-y-0` sets the standalone `translate` property, so `useHideOnScroll`'s bar silently made every `Sheet` opened from it resolve `inset: 0` against a 171px box instead of the viewport. ⚠️ Walking ancestors for `transform` will NOT find it: `transform` reads `none` while `translate` reads `0px`. The fix is a PORTAL to `document.body`, never a `max-height` (that just makes the clipped panel scrollable inside the wrong box). Diagnose by comparing against a control: append your own `fixed inset-0` div and read both heights. → [[fixed-overlay-containing-block]]
- **Three ways hover breaks, and one way a working hover LOOKS broken.** Tailwind v4's preflight leaves `<button>` at `cursor: default` (fixed once in a `@layer base` rule; a per-component fix never finds it). A `hover:bg-*` utility cannot beat an inline `style={{ background }}`. Put the values in custom properties and let utilities switch them. ⚠️ **A browser pane that isn't displayed stops compositing**, so `getComputedStyle` returns the START value of every transitioned property, `layout-shift`/CLS report zero whether or not the bug exists, and `(hover: hover)` is FALSE. ⚠️ **It starves the whole RENDERING LOOP, not just paint**: `requestAnimationFrame`, `ResizeObserver` and `IntersectionObserver` all silently never fire, so a layout that re-fits on resize and a lazy-load sentinel both look permanently broken while `clientHeight` updates correctly. Two false positives in one sweep. Inject `* { transition: none !important }` before measuring, and **run a control** — your OWN observer, against the old code. ⚠️ A tab that was never fronted reports `innerWidth: 0`, so `100dvh` is 0 and every geometry read is garbage; assert `innerWidth > 0` in the same probe. → [[hover-and-cursor-traps]]
- **Platform colour-coding is removed site-wide. Identify a provider by its LOGO via `<BrandGlyph source="…">`, not its hex.** No brand hue in ANY state, hover included. `TYPE_COLORS` (game/movie/show) is a different axis and stays. ⚠️ The sweep missed one inline hex for five days, so **grep for a hex** before repeating "site-wide". simple-icons ships WORDMARKS that are illegible below ~20px. → [[platform-brand-marks-not-colours]]
- **"The nav reaches every page" is not the same claim for every session state.** `AppNav`'s "You" slot is a link for a signed-in visitor and a `SignInDialog` button for an anonymous one, and `/profile` additionally `router.replace("/")`s anon before its footer renders. Verify a reachability claim separately for every auth branch the nav renders differently for. → [[anon-legal-reachability]]
- **`truncate` does nothing without `min-w-0`.** Verify any mobile layout at 320/360/412. → [[mobile-viewport-overflow]]
- **`/library`, `/wishlist`, `/settings` and the FACET pages are dead under `next dev` only**. Use the `prod` launch config to verify them. ⚠️ `/settings` renders the SIGNED-IN chrome with every field empty rather than a spinner, which reads as data loss. → [[unhydrated-page-diagnosis]]

### Design tokens

- **A `@theme` custom property read ONLY through an inline `var()` is TREE-SHAKEN**. It resolves to `""`, the declaration is invalid, and the element inherits. No build, lint or test error. Declare such tokens in a plain `:root` block instead. Check with `getComputedStyle(document.documentElement).getPropertyValue('--your-token')` returning `""`. → [[tailwind-theme-tree-shaking]]
- **A token's `@theme` prefix must be the utility's OWN theme key, and a wrong prefix generates NO RULE AT ALL.** `duration-*` resolves from `--transition-duration-*`, so `--duration-base` left ~28 call sites at Tailwind's default 150ms for three weeks with everything green. **Read the utility's actual theme key** (`grep -o '"duration",[^;]\{0,300\}' node_modules/tailwindcss/dist/lib.js` prints its `valueThemeKeys`) and **verify a matching RULE exists, not that the token resolves**. The token resolving proves nothing here. ⚠️ A naive `document.styleSheets` walk gives a FALSE NEGATIVE (CSS nesting gives every `CSSStyleRule` an empty `.cssRules`); test `selectorText` first and only recurse when `length > 0`. Note the scanner reads MARKDOWN too, so doc prose emits real rules, so "the rule exists in prod" is not proof a component uses it. → [[tailwind-theme-tree-shaking]]
- **`personKey`/`slugify`: NFD does not decompose `ø å æ ł ß`.** Never give `tagKey` the same fix. → [[unicode-normalization-lossy-slugs]]
- **Rank a selection by the same quantity the thing it feeds is made of, and name the input a row was actually computed from.** The Score's top-N buckets sorted by raw `dev` while a facet contributes `dev · classWeight · gain`, so a heavier facet worth more points lost its slot and the panel printed a greyed "not counted" row worth twice the counted one above it. Same function, second instance: a `reasons[].category` carrying the ITEM's category while the weight came from the profile's EFFECTIVE one. ⚠️ `CATEGORY_LABELS` is nine STATIC ids and the taxonomy is EDITABLE. Resolve a label against the live list, fall back to the id, never to a flat "Tag". ⚠️ `docs/fandex-score.md` §3.3 specified the correct sort from day one and the code never matched it; diff a spec that specific against the implementation. → [[fandex-score-h5]]

### Tooling and lint

- **A type-only import must be written `import type`**, an eslint ERROR here, and not style. Node's native type-stripping (what `scripts/alias-hooks.mjs` gives every standalone `.mjs`) erases only *syntactically* type-only constructs, so a plain `import { Foo }` of an interface throws `SyntaxError` the moment a script reaches that module, while tsc, vitest, `next dev` and `next build` all elide it silently. Every export of `src/types/index.ts` is type-only. → [[db-migrations-and-testing]]
- **Read eslint's `✖` TOTALS line, never `tail` its output.** The LAST line is the FIXABLE summary — "0 errors and 8 warnings potentially fixable" means none of the errors are auto-fixable, NOT that there are none. The totals line sits above it: "481 problems (1 error, 480 warnings)". A `| tail -2` reads as green and let a CI-breaking error through. `npm run lint 2>&1 | grep -E '^✖'`.
- **Do not run `eslint --fix` broadly without diffing for non-import changes**. It rewrote three `{/* eslint-disable-next-line */}` JSX comments to a bare `{ }`, destroying the directives while looking inert. → [[eslint-fix-mangles-jsx-comments]]
- **A `//` comment in JSX CHILDREN position is a TEXT NODE and renders on the page.** A *refactoring* hazard: wrapping an existing `return ( … )` in a fragment moves any `//` comment from JS position into children position. Valid JSX, so tsc, lint, tests and the build all pass. Only a human looking at the page catches it. `react/jsx-no-comment-textnodes` is now an ERROR. Re-check every comment inside a `return` you just wrapped. → [[jsx-comment-in-children-renders]]
- **`npm run lint` scans the whole cwd with no path filter**, so a stray `git worktree` under `.claude/worktrees/` gets scanned, gitignored or not (`eslint.config.mjs`'s `globalIgnores` excludes it now). If lint reports a wall of errors you don't recognize, check `git worktree list` before assuming you broke something, and **never delete a worktree you didn't create**. It may be another session's live work. Browser-verifying from a worktree needs a real `npm ci`; a `node_modules` junction fails. → [[worktree-needs-real-npm-ci]]
- **The `react-hooks/*` rules are ERRORS and the repo is error-clean.** Remaining `set-state-in-effect` flags sit on genuinely idiomatic patterns (storage hydration, prop→state sync, fetch-on-mount, load guards, layout measurement) with justified disable comments. Don't remove one without checking why it's there.
- **A push that doesn't reach prod is a CI problem until proven otherwise**. Healthy push→live is 3–5 min. → [[ci-red-blocks-railway-deploy]]

### Measurement discipline

- **Measure before optimising.** §A was mis-sized by 100× once, and a 58 s cold Discover load was blamed on the catalog pool for days when the pool rebuild is ~430 ms. Payload beat CPU in the one full audit. → [[perf-audit-2026-07-30]]
- **Take a time series, never a spot sample**, for prod memory, cost or DB growth. Across four incidents the obvious culprit was wrong every time, and **a WAL that will not truncate is a symptom to chase, not a high-water mark to document** (`shadowWalMb` moving across a restart separates the two). → [[prod-incidents]], [[wal-highwater-vs-litestream-stall]]
- **Price a feature in RAM, not disk**. Memory is 77% of the Railway bill and volume ~9%, so disk is ~75× cheaper. Catalog size is a resident-pool cost first. → [[railway-cost-shape]]
## Model/agent routing for this repo

The main session's model is whatever the human picked — this doesn't change that. It guides which model/agent tier to reach for when *delegating* via the Agent/Task/Workflow tools:

- **Bulk file search / "where is X" exploration** → the `Explore` agent at the default model. Cheap, fast, keeps the main context clean.
- **Mechanical doc maintenance** (archiving a finished phase, reformatting, renaming) → fine to delegate at low effort. Low blast radius, easy to review the diff afterward.
- **Anything touching `migrations.ts`, `matcher.ts`'s write paths, sync/pull adapters, or auth/session code** → do NOT delegate to a background/low-effort agent. These carry the invariants above (a mistake risks data loss or an auth hole) — do this work in the main loop at full effort, and verify against real `data/rr.db` behavior rather than trusting green tests alone (see [[db-migrations-and-testing]]: every DB test starts fresh, so none of them exercise the upgrade path production actually takes).
