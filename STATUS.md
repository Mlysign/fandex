**👉 2026-07-28: Calendar now shows three sources, and every list page shares one header order.** Nils's feedback, built + verified same session (IDs `L1`–`L8` in TASKS.md). **Calendar** was wishlist-only; it now has a Wishlist/Library/**Popular** chip row (all three on by default), with Popular coming live from the providers per visible month via the new `GET /api/calendar/popular?month=YYYY-MM`. That needed two new pieces: `monthWindow()` (nothing in the codebase could ask a provider for a specific month — only "18 months forward/back"), and `src/lib/popularMonth.ts`, which ranks across sources by scoring each candidate against the **median of its own source+type bucket** — provider popularity numbers aren't comparable, so a raw sort would just rank by whichever API uses bigger integers. The resulting type mix is deliberately uneven (July 2026: 7 movies / 8 games / 0 shows; May 2026: 10 games / 4 movies / 1 show). Also on Calendar: the yellow current-month tint and both "previous/next release" jump pairs are gone, **Today** is a real tap target, and **day cells went 40.7×128 → 50.8×80 at 375px**. **Globally**, `SubBar` is now the one page header for Home/Discover/Library/Wishlist/Calendar in a fixed order — **type filters → tabs → search → content** — with every list-page headline removed (`sr-only` `<h1>`s keep the document outline) and advanced filters collapsed behind a badge-counted trigger on desktop as well as mobile. Found and fixed in passing: **`/api/home` was minting `media_items` rows for anonymous visitors**, the exact PR15 rule its own comment claimed to follow. 362 tests + typecheck + 0 lint errors, verified logged-in in the browser. **One accepted trade-off:** Library/Wishlist's sticky header is 207px (25%) at 375px.
